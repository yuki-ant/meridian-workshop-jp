GOAL  このリポジトリの code-reviewer サブエージェントに今日の変更をレビューさせ、参加者が直す指摘を選び、修正してコミットする。

SAY
- 納品前に、別の目でレビューします。このリポジトリの `.claude/agents/code-reviewer.md` に、レビュー専門のサブエージェントを用意してあります。サブエージェントは、別の文脈で特定の仕事だけをする Claude です。作業した本人とは違う目で読めるのが利点です。
- どの指摘を直すかを決めるのはあなたです。

YOU DO
1. 次を送ってもらう。

[PASTE BLOCK]
code-reviewer サブエージェントで、tutor-base から今までの変更（git diff tutor-base..HEAD の client/ と server/）をレビューしてください。

2. Agent ツールで code-reviewer サブエージェントを呼ぶ（subagent_type: code-reviewer）。渡すのは、対象のファイル、今日の範囲（A と B）、範囲外にした項目（Reports ページ、発注書機能、Composition API への移行など）。範囲外の指摘は「次フェーズ」に分ける、と頼む。
3. 結果は全文を貼らず、重要度別（🔴 直すべき／🟡 できれば／🟢 参考）に1行ずつ、多くて6件にまとめる。
4. AskUserQuestion（multiSelect）で、どれを直すかを参加者に選んでもらう。🔴 は推奨として先頭に置く。直さないものは引き継ぎメモに回す、と伝える。
5. 選ばれた指摘を直す。再確認は軽くでよい: バックエンドを変えたならテストを実行し、画面に効く修正ならブラウザで一目見てもらう。
6. コミットしてよいか聞いてからコミットする。例: `R1: レビュー指摘の修正`。直すものがなかった場合はコミット不要。

RECORD  （最終レポートで詳しく書くため、2つ記録する）
- review=<直した指摘と、次フェーズに回した指摘を短く>
- review_findings=<指摘ごとに「重要度|指摘|場所（ファイル:行）|何が問題か|判断（修正／次フェーズ／見送り）|修正内容」を「 ;; 」区切りで。全件>

DONE WHEN  レビューの結果と参加者の判断が記録され、client/ と server/ に未コミットの変更がない。
